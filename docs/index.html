scry.nvim

A ledger of what you believe about your code.

Git records what happened. scry records what you think is true — and tells you the moment the code stops agreeing.

A lint failure means the code is wrong.
A divergence means someone is wrong,
and deciding who is the product.

I

The glass

One editable buffer holding your whole model, with the verdicts rendered beside it. Your beliefs are the text; everything to the right of them is scry's answer — computed, never stored.

An illustration, not a screenshot. The header, the verdicts and the evidence line are virtual text — none of it is in the buffer.

Editing the model is the primary gesture, and :write saves it, routing never-claims out to the holdout and announcing where they went. "Files on disk" is not decoration: scry reads saved files, so an unwritten buffer is invisible to it. A verdict is always presented with when it was computed and against what.

The four verdict counts always sum to the claim count. The unchecked column appears only when it isn't zero, so that "0 missing · 0 violated" can never be read as a clean bill of health for claims no engine ever answered.

II

The map is prose plus claims

Plain text, versioned with the code it describes, and lossless — parse then serialize returns the identical bytes. That is what makes editing the model safe.

.scry/map.scry
# providers
  files lua/conjurer/providers/*.lua

  The provider layer turns a Request into text and calls back once
  on the main loop. Transport only: no UI, no lists.

  contains
    lua/conjurer/providers/cli.lua:request    -- @w0zro 2026-07-26 3f9a01
    lua/conjurer/providers/known.lua:resolve
  calls
    known.lua::resolve
  never
    vim\.ui\.
  exercises
    tests/cli_spec.lua:a provider calls back exactly once
  • Everything that isn't a claim is prose — preserved verbatim, never checked, never marked. There are no parse errors: a line is a claim or it is prose. The sentences carry the theory; the claims carry the check, and that split is the whole trick.
  • Indentation is the grammar; vertical space is layout. A blank line does not close a claim block, so you can paragraph a long list of prohibitions and every one is still a claim.
  • never patterns are raw ripgrep regexes — vim\.ui\., not vim.ui.*. No sugar, because silently mis-escaping a prohibition is exactly the quiet overclaim scry exists to prevent.
KindTargetClaims
containspath:symbola definition exists at that location
calls[hint::]symbolthe target exists, and this concern references it
nevera ripgrep regexzero matches in the concern's files
exercisespath[:assertion]that spec passes

Two axes, not four items

static evidence

contains · calls · never

A definition node, a text match. Cheap, side-effect-free, recomputed on every check.

dynamic evidence

exercises

Something was run and it passed. Slow, stateful, and stale the moment you edit.

Structural claims say where things are; an exercised claim says what holds. Neither axis is the primary one. Adding a feature usually wants one of each — contains for the thing existing, exercises for it working — and fixing a bug often wants only the second, since nothing structural changed.

III

The glyph never appears alone

Every label states what was actually checked. The fidelity of the evidence travels with the verdict, so the glass cannot render a stronger word than the engine that produced it.

✓ defineda definition node with that name exists (treesitter)
✓ referenced (text)the token occurs in the concern's files (ripgrep)
✓ no matches (rg)the prohibition found nothing
✓ passing (ran 4m ago)that spec exited 0, and nothing it depends on has changed since — the age is part of the verdict
✗ absentthe definition, or the target, does not exist
✗ unreferencedthe target exists, but this concern never mentions it
✗ VIOLATEDa prohibition matched — carries the line that proves it
✗ FAILINGthat spec exited non-zero — carries its output
∅ unratifiednobody has put their name on this claim
– uncheckedno resolver for this language. Not a pass.
– unrunnobody has run that spec yet. Not a pass.
– staleit passed, but the code has moved since. Not a pass.
– vacuous?it passes, and nothing its concern claims exists yet — so it asserts nothing. Not a pass.
the asymmetry A violated prohibition is proof, and it carries the line that proves it. A clean prohibition is evidence, not proof — no textual match is not absence of behaviour.
◈
IV

The seal

:ScryRatify — ratification, the smallest act that puts a person back in the loop. Your name, the date, and the head of a hash of the claim's own text.

a sealed claim
lua/auth.lua:create_session  -- @w0zro 2026-07-26 6b8f0e

Because the hex is sha256 of the claim text, staleness is mechanical and free: edit a claim and it is unratified again, since the hash no longer matches. No hooks, no hidden state, and the seal shows up in git diff like any other line.

Why bother? Because you cannot write down a belief without having one. Clicking "accept" is free, which is why approval degenerates into LGTM. Asserting "this concern contains X and never touches Y" is not performable by someone who hasn't looked, and a careless assertion diverges later with your name on it.

not the same as repairing the theory A program's theory lives in the people who built it and cannot be fully written down. scry does not try to capture it and cannot restore it once it is gone. What it does is narrow the drift, and make the moment you stopped understanding something visible instead of silent — a distinction that matters more, not less, the less code you write by hand. A seal is a record of intent, not authenticated attribution: @name is whatever git config user.name says.

V

The reckoning

Theory-debt: two numbers, never blended into a score. They mean different things, and a single fraction would hide both.

has a person been here

∅ unratified

Claims nobody has sealed, or whose text has changed since the seal.

does reality agree

✗ diverged

Claims that are missing or violated. A claim can count on both axes, and each counts it once.

The claim count leads every rendering, deliberately: 0 diverged / 3 claims means your map is thin, not that your repo is healthy. Conjuring generates this debt at machine speed; sealing is the only thing that pays it down.

lua
require("scry.debt").statusline()  --> "scry 14c ✓11 ✗2 ∅3"

Gains a –N when anything is unchecked, for the same reason the header does.

VI

The rule it never saw

A never claim is a holdout: withheld from the generator, checked afterwards. That restores independence mechanically rather than by good intentions.

If the model writing your code is also shown the prohibition, its output satisfying that prohibition tells you nothing — it was asked to satisfy it. A prohibition it never saw, checked after the fact, is real evidence. This is why prohibitions and positive claims are stored apart: never-claims live outside the repository by default, under stdpath("state"), keyed to the project path. The glass still shows them inline — only storage differs.

i Withheld from requests — guaranteed, and covered by tests. Everything scry hands a conjurer is built from the concern name, the claim's own target, and the intent you typed. Concern prose is excluded on purpose: prose can restate a prohibition in words no scrubber could catch, so the channel is closed rather than filtered. A tripwire re-checks every outgoing string and refuses to seed if a prohibition's text appears in one.
ii Hidden from the filesystem — only from a generator that reads your repo. Not from one instructed to hunt your disk. Independence here is against leakage, not against an adversary.
the cost, stated plainly Out-of-repo prohibitions are per-machine and unversioned. Setting holdout_path to an in-repo file shares them with your team and gives up the second guarantee — :checkhealth scry warns when you do.

VII

An absent claim is a piece of work

:ScryCascade seeds the quickfix list with the target site and your intent, then hands off to conjurer, which owns the casting and the review. scry never conjures anything itself.

When you save a file the cascade seeded, scry re-checks: the withheld prohibitions run against the new code, and the claim that started the work re-checks too. So the loop closes visibly — ✗ absent becomes ✓ defined · ∅ unratified, and the seal is the act that finishes it. Saving is the trigger because ripgrep reads disk.

The order is the mechanism

Both contains and exercises cascade, and which comes first is not a convention:

i:ScryCascade the absent exercises claim conjures the check
iiRead it, and seal it the judgment act — the one step no mechanism can perform for you
iii:ScryRun it must come back red
iv:ScryCascade the absent contains claim conjures the code, with the spec withheld
v:ScryRun green — and the holdout re-checks
vi:ScryRatify the claim inventory becomes owned product

If the check and the code are both generated from the same claim they are not independent — they are two samples from one generator reading one sentence, so they share its misreadings. Both can be confidently wrong in the same direction and the suite is green. When a person wrote the code, their reading of the claim was an independent sample; remove that and ✓ passing decays into the generator was self-consistent.

Two things restore it, and both are enforced rather than advised. The spec is withheld from the code request — cascading a contains claim adds every spec path in that concern to the tripwire, exactly as it adds the prohibitions, and an intent that names the test is refused. And a check written before the code must fail — one that passes against a feature nobody has built asserts nothing, which is the commonest way a conjured test is worthless and is invisible from inside the run, since the process exits 0 either way.

three limits Withholding a spec is weaker than withholding a prohibition: a never-pattern can live outside the repository, but a spec has to be in the tree to run, so this is request-level withholding only. The seeded entry points at the target file's first line, because scry knows which file should define a symbol, not where in it — so the model decides placement and the review is where you check it. And calls and never claims do not cascade; neither has a single obvious site to seed, and guessing one would be worse than refusing.

VIII

Checking never runs anything

:Scry reads what the last :ScryRun recorded. Only :ScryRun executes.

That separation isn't laziness about performance. Every other verdict is a static read: cheap, repeatable, harmless to recompute on every render. Running a suite is slow, has side effects, and can hang — and a glass that shelled out to your test suite whenever you opened it is a glass you would stop opening.

The price is staleness, and staleness is the danger

✓ passing from before your last edit looks like the strongest thing scry renders and is the easiest one to be wrong. So a recorded run is reported as a pass only while nothing it depended on has moved. Each run fingerprints the concern's files and the spec as it starts; a later check compares. Any difference and the verdict degrades to – stale, which lands in the unchecked column, where an unanswered claim belongs.

fingerprints, not timestamps mtime granularity is one second, and "edit, then run" finishes inside a single tick — so a clock comparison would call every fresh run stale forever. Two claims on one spec are one execution, and its recorded dependencies cover every concern that exercises it.
a named assertion is a weak check spec.lua:some label verifies that the label appears in the spec's source and that the file passes. It is not proof the labelled assertion ran — scry does not see inside a run, it sees an exit code.

X

What scry will not say

Every line here is a limit scry intends to keep stating plainly. It is a chapter, not a footnote — a tool about honest accounting that overstated its own reach would refute itself.

"Backed" means accounted for, not correct. The ladder is claimed → backed → exercised. Nothing scry renders is evidence that your code is right.
contains ✓ defined asserts a definition with that name exists in that file. It says nothing about its body, and the prose above it is unchecked.
calls ✓ referenced (text) asserts the token occurs in the concern's files and the target exists somewhere. It is not a resolved call: not reachability, not the same symbol, not proof the call happens. The rung is referenced < resolved < exercised.
never ✓ no matches (rg) asserts no textual match. It is not absence of behaviour — local ui = vim.ui; ui.input(...) defeats it.
exercises ✓ passing asserts a spec process exited 0, at a stated age, with its dependencies unchanged since. It is not proof a feature works — only that whatever that spec checks, held.
Verdicts describe saved files at a moment. Unwritten buffers and edits made after the check are invisible. The timestamp travels with the render.
Holdout independence is against leakage, not adversaries — and withholding a spec is weaker still, because the spec has to live in the tree to run.
Theory-debt is coverage-blind. Until scry reports code that no claim covers, a clean map may simply be an empty one — which is why the claim count is rendered first.
Seals are records, not identity. @name comes from your git config.
– unchecked is not a pass. A language with no resolver renders as unchecked, deliberately, so silence never looks like agreement.

The state you create on purpose. A new feature is a claim that isn't true yet; a bug fix is a check that doesn't pass yet. Your whole worklist lives here, in the same vocabulary as everything already done. :ScryCascade takes it from here.

Broken
something regressed, each verdict carrying its evidence
✗ VIOLATEDa prohibition matched — with the line that proves it
✗ FAILINGa spec exited non-zero — with its output
✗ unreferencedthe target exists; this concern never touches it

A violated prohibition is proof. A clean one is only evidence — no textual match is not absence of behaviour.

Unknown
what the glass won't guess at — never counted as done
– uncheckedno resolver for this language
– unrunnobody has run that spec
– staleit passed, but the code has moved since
– vacuous?it passes while nothing it covers exists yet

One change, end to end

a feature or a fix, without leaving the glass
say what you want
Write the change as a claim on the product.
It surfaces ✗ absent — to do, named. If you can't state it as a claim, you don't know what you're asking for yet, and the glass just told you that for free.
get the proof first
Cascade the exercises claim before the code.
The check is conjured, you read it — it's short, and it says what "done" means — and :ScryRun must come back red. A check that passes against nothing asserts nothing.
let the conjurer type
Cascade the contains claim.
The code lands with the concern as context — and with this concern's never rules and spec paths withheld. A model that can read the check writes to pass the check; one that never saw it, checked after, produced evidence.
and it's yours
:ScryRun goes green.
You named it, sent it, read the check, watched red become green. The ∅ clears itself — the work passed through your hands, and scry saw it happen.

The trail

the work leaves a trail
authored · cascaded · red → green · settled
Doing the work leaves a trail on the claim it touched: you typed it, you cascaded it, its check failed and then passed under your :ScryRun, it came true on your save. A claim is yours when the trail shows you passed through it — and a machine-drafted claim nobody has engaged with stays ∅ untouched, which is the point. Edit a claim and its trail resets — every event is keyed to a hash of the claim's text.

Five commands

zero config works · :h scry is the manual
CommandDoes
:ScryOpen the glass; check every claim.
:ScryCheckRe-check against the files on disk.
:ScryCascadeConjure the absent claim under the cursor, prohibitions withheld.
:ScryRunRun the specs behind exercises claims, then re-check. The only command that executes your code.

The glass doesn't flatter

its limits, stated as plainly as its verdicts
The map is yours either way. A model may draft it — a draft arrives untouched. The danger was never half-right guesses; it's unowned claims that read as understood. Working through one is what makes it yours.
Backed is not correct. claimed → backed → exercised. Nothing here says your code is right.
contains ✓ — a definition with that name exists. Nothing about its body.
calls ✓ — the token occurs and the target exists. Not a resolved call.
never ✓ — no textual match. local ui = vim.ui defeats it.
exercises ✓ — a process exited 0, at a stated age. Not proof a feature works.
Verdicts describe saved files. Unwritten buffers are invisible; the timestamp travels with the render.
Withholding guards against leakage, not adversaries. A spec must live in the tree to run, so hiding it is request-level only.
The cascade seeds the file's first line. scry knows which file, not where in it. Placement is the model's call; review is yours.
The trail is per-machine. Ownership lives in local state like run results — a teammate's glass shows their trail, not yours.

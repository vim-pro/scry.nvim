Operators, one noun up

you already know the grammar

Vim's bargain is operators × text objects.

d2w, ci", >ap — small orthogonal verbs applied to precisely addressed nouns, repeatable with ., fannable with :g. That grammar is why vim outlived every editor that set out to replace it.

conjurer.nvim ported the grammar to generated edits: ~{motion} is an operator whose effect is rewrite this region toward an intent. Same verbs, same nouns, a new effect.

conjurer ~ap a region in a file
→
scry ~ a capability, across every file it is made of

scry raises the noun. Not a region in a file — a capability. The glass is not a report you read; it is the noun-space you aim at.

Put the cursor on Tailor a checklist to your own situation, press ~, say what you want. The change lands across compile.ts, c/[slug].astro, copy.astro and c/index.astro. Four files, one intent, and you never opened one.

. repeats it on the next feature. :g/^feature.*export/normal ~ fans it across every capability that matches. Nothing new to learn.

Adding a capability is the same verb, because an address exists before the file does: route print names src/pages/print.astro whether or not anything is there yet. Write the feature you want with the members it should have, and cast — absent members are files to create.

Everything else here exists to make that address real. The checks say whether what you asked for actually landed. The kinds say where a member's file lives. Neither is the point. The point is that a capability has an address you can put a cursor on.

What the glass shows

features are the line you scan · claims are the evidence under them
Done
the product does what you said it does
✓ doneevery piece of evidence under this feature holds
✓ definedthe thing exists, where you said
✓ referenced (text)the connection you described is there
✓ no matches (rg)the rule holds
✓ passing (ran 4m ago)the behavior holds, as of moments ago
To do
what you've named and not yet made
✗ not yeta feature with nothing holding under it
◐ 2 of 5real progress — some evidence holds
✗ absentone claim: named, not yet real

The state you create on purpose. A new feature is part of the product that isn't real yet; a bug fix is a behavior that doesn't hold yet. Your worklist and your product are the same document. :Conjure takes it from here.

Broken
the product stopped doing what you said — with proof
✗ broken (1 of 4)a feature that regressed; outranks everything else
✗ VIOLATEDa rule was broken — with the line that broke it
✗ FAILINGa behavior regressed — with the failure in hand
✗ unreferenceda connection you described no longer exists

A broken rule is proof. A rule that merely looks intact is evidence — the glass keeps that distinction for you.

Unknown
what the glass would rather admit than guess — never counted as done
– uncheckedthe glass can't read this part yet
– unrunnobody has asked for proof yet
– stalethe proof predates your latest change
– vacuous?it passes while proving nothing
– unscopeda rule on a feature that locates nothing yet
And one number that isn't about any feature. A map whose features all read ✓ done can still describe a fraction of the product, so the header counts the files no feature claims — 12 unclaimed files — and :ScryUnclaimed lists them. Each one is a decision: give it to the feature that owns it, or name the feature nobody wrote down. Without this, "everything done" would be unfalsifiable.

One change, end to end

a feature or a fix, without leaving the glass
name it
Describe the change as part of the product.
It surfaces as work to do. If you can't describe it, you don't know what you're asking for yet — and finding that out took one sentence instead of one afternoon.
the proof comes first
Before any code, you get the test.
Short, readable, and it fails — the feature doesn't exist yet. Reading it is how you check the machine heard what you meant, while it's still one page instead of a diff.
let the conjurer type
The code arrives knowing the product — not the answers.
Your rules and your test were kept from it. A model that can see the test writes to pass the test; one that never saw it, checked after, actually proved something.
and it's yours
The proof passes, and the work is yours.
You asked for it, read the test, watched fail become pass. The glass saw all of that happen — so it already knows whose work this is.

The trail

the work leaves a trail
authored · conjured · red → green · settled
Work leaves a trail on whatever it touches: you described it, you conjured it, you watched its proof fail and then pass, it came true under your hands. A piece of the product is yours when the trail shows you passed through it — and a machine-drafted piece nobody has engaged with stays ∅ untouched, which is the point. Change the description and the trail resets.

Five commands

zero config works · :h scry is the manual
CommandDoes
:ScryOpen the glass. Everything is checked the moment you look.
:ScryCheckLook again — fresh verdicts from what's on disk.
:ConjureMake the thing under the cursor real — the same verb that conjures over a motion in code.
:ScryExerciseRun the proofs. The only command that executes your code.
:ScryUnclaimedList the files no feature claims, in the quickfix list.

The glass doesn't flatter

its limits, stated as plainly as its verdicts
The description is yours either way. A model may draft it, and a draft arrives untouched. The danger was never wrong guesses — it's unowned pieces that read as understood.
Done means accounted for, not right. The glass says the product matches its description — not that the description was wise.
Every ✓ names its evidence, and never claims more than what was actually seen. The full ladder of what each label does and doesn't assert is a chapter of the manual.
A rule can be dodged in ways the glass can't see. That's why a broken rule is proof and an intact one is only evidence.
The glass reads saved work. What you haven't written yet is invisible, and every answer says when it looked.
Kept-back rules guard against leakage, not adversaries. They keep honest generations honest; they don't survive a hunt.
The conjurer chooses placement. The glass knows which file the work belongs in, not where in it. Review is yours.
The trail stays with you. A teammate's glass shows their work, not yours.
